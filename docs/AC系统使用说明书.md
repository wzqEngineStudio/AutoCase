## 1. 系统概述

### 1.1 系统定位

AutoCase（简称AC系统）是一款面向个人开发者的 AI 用例驱动自动化测试管理系统。系统的核心理念是：**只要 AI 生成的测试用例符合规范格式，系统就能自动识别、解析并执行**。

### 1.2 核心能力

- **AI 用例原生兼容**：以 `*Case.json` 文件为用例载体，AI 输出的 JSON 符合规范即可直接导入使用
- **多语言脚本执行引擎**：支持 Python / GDScript / Java / C / C++ / Go / Rust / JS / TS / Ruby / Shell 等语言
- **用例-脚本自动关联**：通过名称模糊匹配自动绑定测试脚本与用例 JSON
- **手工+自动化双轨**：支持传统手工测试和全自动脚本批量执行
- **完全离线运行**：数据存储在本地，不依赖任何远程服务

### 1.3 设计边界

本系统面向个人开发者，以下能力不在范围内：
- 不提供缺陷提单 / 工单流转（不对接 Jira、禅道等）
- 不提供多人协作 / 权限管理
- 不与研发代码仓库做 CI/CD 集成
- 不做服务端部署（纯桌面端应用）

## 2. 安装与启动

### 2.1 环境要求

| 项目 | 要求 |
|------|------|
| JDK | 17 或更高版本 |
| 操作系统 | Windows / Linux / macOS |

### 2.2 启动方式

#### 方式一：运行打包好的 JAR

```bash
java -jar autocase-1.1.0.jar
```

#### 方式二：从源码构建运行

```bash
# 克隆仓库
git clone https://github.com/wzqEngineStudio/AutoCase.git
cd AutoCase

# 打包
mvn clean package

# 运行
java -jar target/autocase-1.1.0.jar
```

### 2.3 首次启动

1. 启动后会自动创建配置目录 `~/.cms/`
2. 点击「选择根目录」按钮，选择包含用例文件的项目目录
3. 系统会自动扫描并加载目录下的所有 `*Case.json` 文件

## 3. 功能模块使用指南

### 3.1 用例管理

用例管理模块是系统的核心，负责管理测试用例文件。

#### 3.1.1 界面布局

- **左侧资源管理器**：以目录树形式浏览项目文件，用绿色标识包含用例的目录
- **右侧用例列表**：显示所有已加载的用例，支持筛选和搜索

#### 3.1.2 操作说明

| 操作 | 说明 |
|------|------|
| 选择根目录 | 点击顶部工具栏「选择根目录」按钮，选择项目根目录 |
| 新建用例 | 在资源管理器右键菜单中选择「新建用例」，或点击列表上方「新建」按钮 |
| 编辑用例 | 双击用例列表中的记录，或选中后点击「编辑」按钮 |
| 删除用例 | 选中用例后点击「删除」按钮，确认后删除（不可恢复） |
| 添加到任务 | 选中用例后点击「添加到任务」，可将用例关联到手工测试任务 |
| 搜索用例 | 在搜索框输入关键词，支持按名称模糊搜索 |
| 筛选用例 | 使用下拉框按状态、严重程度、优先级筛选 |

#### 3.1.3 用例状态说明

| 状态 | 含义 |
|------|------|
| UNVERIFIED | 未验证，初始状态 |
| PASSED | 通过 |
| FAILED_NOT_REGRESSED | 失败 |
| BLOCKED | 阻塞 |
| SKIPPED | 跳过 |

### 3.2 Git仓库

Git仓库模块提供 GitHub 操作功能。

#### 3.2.1 功能说明

- **一键 Push**：将当前目录的变更推送到远程仓库
- **仓库配置**：设置 GitHub 仓库地址和认证信息

#### 3.2.2 操作步骤

1. 在设置面板中配置 GitHub 用户名、邮箱和仓库地址
2. 切换到「Git仓库」标签页
3. 点击「Push to GitHub」按钮完成推送

### 3.3 手工测试

手工测试模块支持传统的手工测试任务管理。

#### 3.3.1 三层结构

```
任务组 → 任务 → 用例执行记录
```

#### 3.3.2 操作说明

| 操作 | 说明 |
|------|------|
| 创建任务 | 点击「新建任务」，填写任务名称、版本、模块、测试人 |
| 添加用例 | 在用例管理面板选中用例，点击「添加到任务」 |
| 执行用例 | 在任务详情中逐条执行，记录实际结果 |
| 标记状态 | 支持 PASS / FAIL / BLOCKED / SKIPPED 状态 |
| 记录附件 | 可添加截图或其他附件路径 |

### 3.4 自动化测试

自动化测试模块是系统的核心功能之一，支持多语言脚本的批量执行。

#### 3.4.1 功能特性

- 自动扫描目录下的测试脚本文件
- 多线程并行执行（按 CPU 核心数）
- 优先级排序（P0 优先 → 步骤数短优先）
- 超时熔断（默认 60 秒）
- 崩溃检测和暂停/停止控制
- Debug 日志自动收集与过期清理

#### 3.4.2 操作步骤

1. 切换到「自动化测试」标签页
2. 系统自动扫描并列出可用脚本
3. 勾选需要执行的脚本（默认全选）
4. 点击「开始执行」按钮
5. 实时查看执行进度和结果

#### 3.4.3 结果判定规则

| 输出/退出码 | 判定结果 |
|-------------|----------|
| 包含 "PASS" | PASSED |
| 包含 "FAIL" | FAILED |
| 包含 "BLOCK" | BLOCKED |
| 退出码 != 0 | FAILED |
| 执行超时 | TIMEOUT |

#### 3.4.4 支持的语言

| 语言 | 扩展名 | 默认命令模板 |
|------|--------|--------------|
| Python | `.py` | `python "{0}"` |
| GDScript | `.gd` | `godot --headless --script "{0}"` |
| Java | `.java` | `java -cp "{1}" "{2}"` |
| C | `.c` | `gcc "{0}" -o "{1}" && "{1}"` |
| C++ | `.cpp` | `g++ "{0}" -o "{1}" && "{1}"` |
| JavaScript | `.js` | `node "{0}"` |
| TypeScript | `.ts` | `npx ts-node "{0}"` |
| Go | `.go` | `go run "{0}"` |
| Rust | `.rs` | `rustc "{0}" -o "{1}" && "{1}"` |
| Ruby | `.rb` | `ruby "{0}"` |
| Shell | `.sh` | `bash "{0}"` |
| Batch | `.bat` | `cmd /c "{0}"` |

### 3.5 测试报告

测试报告模块自动汇总执行结果，生成统计报告。

#### 3.5.1 报告内容

- **执行统计**：总用例数、通过数、失败数、通过率
- **基线快照**：OS 版本、Java 版本、Godot 版本（如果存在）
- **分布统计**：按严重程度和优先级维度展示
- **详细结果**：每条脚本的执行时间、输出和错误信息

### 3.6 执行历史

执行历史模块记录所有自动化测试的执行记录。

- 查看历史执行记录
- 查看每次执行的详细报告和输出日志
- 清理过期数据
- 删除选中批次

### 3.7 缺陷管理

缺陷管理模块记录测试过程中发现的问题。

#### 3.7.1 缺陷属性

| 属性 | 说明 |
|------|------|
| 缺陷标题 | 缺陷的简要描述 |
| 关联用例 | 发现缺陷的测试用例 |
| 来源 | MANUAL（手工测试）/ AUTO（自动化测试） |
| 严重程度 | CRITICAL / MAJOR / MINOR / TRIVIAL |
| 状态 | OPEN / FIXED / CLOSED / REOPENED |
| 描述 | 缺陷的详细描述 |
| 复现步骤 | 如何复现该缺陷 |

#### 3.7.2 操作说明

| 操作 | 说明 |
|------|------|
| 新建缺陷 | 点击「新建缺陷」按钮 |
| 编辑缺陷 | 双击缺陷记录进行编辑 |
| 删除缺陷 | 选中后点击「删除」按钮 |
| 状态变更 | 在编辑界面修改状态字段 |

### 3.8 设置

设置模块用于配置系统参数。

#### 3.8.1 配置项

| 配置项 | 说明 |
|--------|------|
| 用例格式 | JSON / XML / YAML（默认 JSON） |
| 执行命令模板 | 各语言的执行命令，支持自定义 |
| 判定规则 | PASS / FAIL / BLOCK 的关键词 |
| 执行超时 | 默认 60000ms（60秒） |
| GitHub 配置 | 用户名、邮箱、仓库地址 |
| 布局持久化 | 自动保存窗口布局和最近打开目录 |

## 4. 使用流程

### 4.1 标准工作流

```
1. 准备用例
   ↓
2. 选择根目录
   ↓
3. 编写测试脚本（可选）
   ↓
4. 执行测试（手工或自动化）
   ↓
5. 查看报告
   ↓
6. 记录缺陷（如有）
```

### 4.2 快速上手

1. **准备用例文件**：创建以 `Case.json` 结尾的 JSON 文件，放入项目目录
2. **启动 AC 系统**：运行 `java -jar autocase-1.1.0.jar`
3. **选择根目录**：点击工具栏「选择根目录」，选择包含用例的目录
4. **查看用例**：在「用例管理」标签页查看已加载的用例
5. **执行测试**：
   - 自动化：切换到「自动化测试」，勾选脚本，点击「开始执行」
   - 手工：切换到「手工测试」，创建任务并添加用例

## 5. 数据存储

### 5.1 数据位置

| 数据类型 | 存储位置 |
|----------|----------|
| 用例文件 | 用户指定的项目目录（`*Case.json`） |
| 配置文件 | `~/.cms/cms_config.json` |
| 数据库 | `~/.cms/` 目录下的 H2 数据库文件 |
| Debug 日志 | `~/.cms/debug_logs/`（保留7天） |

### 5.2 数据备份建议

1. 定期备份项目目录下的用例文件
2. 定期备份 `~/.cms/` 目录（包含配置和数据库）
3. 使用 Git 将用例文件纳入版本管理

## 6. 常见问题

### 6.1 用例不显示

**原因**：用例文件命名不符合规范

**解决方案**：确保文件名以 `Case.json` 或 `case.json` 结尾

### 6.2 脚本执行失败

**原因**：
- 执行命令模板不正确
- 缺少对应语言的运行环境
- 脚本语法错误

**解决方案**：
- 在设置中检查执行命令模板
- 确保系统已安装对应语言的运行环境
- 查看 Debug 日志定位错误

### 6.3 用例与脚本无法关联

**原因**：脚本文件名与用例名称不匹配

**解决方案**：确保脚本文件名（去掉扩展名和 Test/Case 后缀）与用例名称一致

### 6.4 中文乱码

**原因**：Windows 控制台编码问题

**解决方案**：系统已内置 UTF-8 编码修复，如有问题请确保 JDK 17+ 版本
